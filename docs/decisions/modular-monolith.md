# ADR-001: 모듈러 모놀리스 아키텍처 채택

## 날짜

2026-05-30

## 상태

Accepted

---

## 맥락 (Context)

SafeCheck는 6개의 기능 도메인을 가진 재난 정보 서비스입니다.

**현재 제약 조건:**
- 1인 개발자 운영
- MVP 단계: 뉴스 기능 1개부터 시작
- AI(Claude, Codex)와 협업하여 기능별 파일 단위 작업
- 향후 WebSocket, 스케줄러, 외부 API 연동 등 복잡도 증가 예상

**검토한 대안:**
1. 계층형 구조 (controllers/, services/, repositories/ 분리)
2. 마이크로서비스 (MSA)
3. DDD 헥사고날 아키텍처
4. **Feature-first 모듈러 모놀리스** ← 선택

---

## 결정 (Decision)

**Feature-first 모듈러 모놀리스** 구조를 채택합니다.

- NestJS 모듈 시스템을 기능 도메인 단위로 분리
- 각 기능 모듈은 `src/modules/{domain}/` 폴더에 완결
- 공유 인프라는 `src/shared/`에 격리
- 스케줄러 인프라(`ScheduleModule.forRoot()`)는 `shared/schedule/`에 1회 등록하고, 크론 로직은 각 도메인 모듈 내부에 위치
- 단일 프로세스로 실행

---

## 결과 (Consequences)

### 긍정적 결과

- **1인 관리 가능:** 전체 구조가 화면 한 스크롤 안에 파악됨
- **AI 협업 최적:** `modules/news/` 폴더 1개 = 작업 컨텍스트 1 청크
- **점진적 확장:** 기능 추가 = 폴더 추가, 기존 코드 변경 최소
- **MSA 전환 경로 유지:** 필요 시 특정 모듈을 별도 서비스로 분리 가능

### 부정적 결과 (감수하는 트레이드오프)

- MSA 대비 장애 격리 없음 (단일 프로세스)
- 모듈 간 의존성 규칙을 개발자가 직접 관리해야 함 → `docs/architecture/module-boundaries.md`로 보완
- 트래픽 급증 시 수평 확장에 제약 (프로세스 전체 복제)

---

## 재검토 조건

아래 상황이 되면 MSA 분리 여부를 재검토합니다.

| 조건 | 설명 |
|------|------|
| 리소스 병목 | 단일 서버 CPU/메모리가 지속적으로 한계에 도달 |
| 팀 규모 확장 | 개발자 3인 이상으로 확장, 도메인별 독립 배포 필요 |
| SLA 분리 요구 | 재난 알림 서비스의 가용성이 다른 기능과 분리되어야 할 때 |
