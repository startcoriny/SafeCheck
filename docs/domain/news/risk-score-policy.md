# 키워드 필터링 및 위험도 산정 정책서

## 1. 목적

네이버 사건사고 섹션의 모든 기사가 SafeCheck에 필요한 사건사고 정보는 아니다.

따라서 수집 후 제목을 기준으로 1차 필터링을 수행한다.

필터링의 목적은 다음과 같다.

- 사건사고와 관련 있는 기사 후보를 선별한다.
- 보험, 금융, 스포츠, 연예, 행사 등 안전과 무관한 기사를 제거한다.
- 위험도 산정에 필요한 키워드를 추출한다.
- 초기 MVP에서 AI 없이도 설명 가능한 기준으로 뉴스 노출 여부를 판단한다.

---

## 2. 필터링 구조

```
기사 제목 수집
↓
포함 키워드 매칭
↓
제외 키워드 매칭
↓
사건 유형 분류
↓
위험도 점수 계산
↓
기준 점수 미만 제외
↓
위험도 등급 부여
```

---

## 3. 키워드 관리 방식

키워드 목록은 코드에 하드코딩하지 않고 별도 설정 파일로 관리한다.

```
keywords/
├─ include-keywords.json
├─ exclude-keywords.json
├─ accident-type-keywords.json
├─ risk-score-rules.json
```

선택 이유:

- 운영 중 키워드를 수정하기 쉽다.
- 오탐 사례가 발견되면 빠르게 제외 키워드를 추가할 수 있다.
- 사건 유형 분류 기준을 서비스 로직과 분리할 수 있다.
- 향후 관리자 페이지에서 키워드 관리 기능으로 확장할 수 있다.

트레이드오프:

- 설정 파일 형식 검증이 필요하다.
- 잘못된 키워드 추가 시 필터링 품질이 떨어질 수 있다.
- 운영 반영 전 테스트 데이터로 검증하는 과정이 필요하다.

## 7. 위험도 산정 기준

위험도는 단순히 사건 유형만으로 판단하지 않는다.

예를 들어 “화재 발생”, “주택 화재”, “대형 물류창고 화재”, “화재로 10명 사망”은 모두 위험도가 다르다.

따라서 위험도는 다음 요소를 조합해서 계산한다.

```
위험도 점수 =
사건 유형 점수
+ 인명 피해 점수
+ 규모 점수
+ 공공 영향 점수
+ 지역 가중치
```

## 14. 최종 필터링 정책

초기 MVP에서는 다음 순서로 처리한다.

```
1. 기사 제목 수집
2. 포함 키워드 매칭
3. 제외 키워드 매칭
4. 사고 유형 분류
5. 위험도 점수 계산
6. 기준 점수 미만 제외
7. 위험도 등급 부여
8. 노출 대상 뉴스로 저장
```

최종 방식:

- 포함 키워드로 1차 후보 선별
- 제외 키워드로 오탐 제거
- 점수 기반으로 위험도 산정
- 기사 URL 기반 고유키로 중복 제거
- 본문/이미지는 저장하지 않고 링크 중심 저장

## 15. 한계 및 고도화 방향

### 한계

- 제목에 명확한 키워드가 없으면 누락될 수 있다.
- “불”, “사고”처럼 의미가 넓은 단어는 오탐을 만들 수 있다.
- 지역명이 제목에 없으면 위치 기반 필터링이 어렵다.
- 같은 사건을 여러 표현으로 보도하면 단순 키워드 방식으로는 정확히 묶기 어렵다.

### 고도화 방향

- 본문 일부 메타데이터 분석
- AI 기반 요약
- 문장 임베딩 기반 유사도 분석
- 지역명 사전 기반 위치 추출
- 사건 단위 incident 그룹핑
- 오탐/미탐 관리용 관리자 페이지
