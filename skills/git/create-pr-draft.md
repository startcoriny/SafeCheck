# PR Draft 생성 Skill

목적

현재 변경사항을 분석하여 GitHub PR 초안을 생성한다.

PR의 목적은 코드 리뷰를 돕는 것이다.

기술 의사결정, 트레이드오프, 상세 설계 내용은 PR이 아닌 ADR 또는 Work Log에 기록한다.

---

## 수행 절차

1. git diff 확인
2. 변경 파일 확인
3. 테스트 결과 확인
4. 변경 목적 파악
5. PR 초안 생성

---

## 출력 형식

```markdown
# Summary

이번 작업에서 무엇을 변경했는지 설명

# Changes

- 변경 사항 1
- 변경 사항 2
- 변경 사항 3

# Test

- npm test 통과
- npm run build 통과

# Related Docs

- 관련 ADR
- 관련 Work Log

# Checklist

- [ ] 테스트 완료
- [ ] 빌드 완료
- [ ] 작업 로그 작성 완료
- [ ] 리뷰 준비 완료
```

---

## 작성 규칙

### Summary

한 문단 이내로 작성한다.

무엇을 변경했는지 요약한다.

### Changes

구현 내용을 나열한다.

변경 파일 목록을 그대로 복사하지 않는다.

기능 단위로 작성한다.

### Test

실제로 수행한 테스트만 작성한다.

실행하지 않은 테스트를 작성하지 않는다.

### Related Docs

관련된 ADR 또는 Work Log를 연결한다.

예시

- ADR-001-project-structure
- WORKLOG-2026-06-01

### Checklist

리뷰 전에 반드시 확인해야 하는 항목만 포함한다.

---

## 금지 사항

- 기술 선택 이유 작성
- 트레이드오프 분석 작성
- 후보 비교 작성
- 장문의 구현 설명 작성
- 변경 파일 전체 나열
- Work Log 수준의 상세 기록 작성

위 내용은 ADR 또는 Work Log에 기록한다.

---

## SafeCheck 규칙

PR은 리뷰용 문서다.

아래 질문에만 답할 수 있으면 충분하다.

- 무엇을 변경했는가
- 테스트했는가
- 관련 문서는 무엇인가

그 외의 상세 내용은 ADR 또는 Work Log에서 관리한다.
