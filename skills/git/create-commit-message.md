# Commit Message 생성 Skill

목적

현재 변경사항을 분석하여 적절한 커밋 메시지를 생성한다.

---

## 수행 절차

1. git diff 확인
2. 변경 파일 확인
3. 변경 목적 파악
4. 커밋 단위 분리 여부 확인
5. 커밋 메시지 생성

---

## 커밋 생성 규칙

커밋 메시지는 아래 형식을 사용한다.

```text
<type>: <변경 내용>
```

예시

```text
feat: 뉴스 목록 조회 API 추가

fix: 뉴스 중복 제거 오류 수정

docs: SafeCheck 아키텍처 문서 추가

refactor: 뉴스 수집 로직 분리

test: 뉴스 서비스 테스트 추가

chore: eslint 설정 추가

perf: 뉴스 조회 쿼리 최적화
```

---

## 생성 기준

### feat

사용자 또는 시스템 기능 추가

예시

- API 추가
- 새로운 모듈 추가
- 새로운 화면 추가

### fix

버그 수정

예시

- 잘못된 응답 수정
- 예외 처리 수정

### refactor

동작 변경 없이 구조 개선

예시

- 함수 분리
- 클래스 분리

### docs

문서 수정

예시

- README 수정
- ADR 추가
- Work Log 템플릿 추가

### test

테스트 추가 또는 수정

### chore

설정 파일 변경

예시

- package.json
- eslint
- prettier
- github action

### perf

성능 개선

예시

- 쿼리 최적화
- 캐시 추가

---

## 출력 형식

```markdown
## 추천 커밋 메시지

feat: 뉴스 목록 조회 API 추가

## 변경 요약

- NewsController 추가
- NewsService 추가
- 뉴스 목록 조회 API 구현
```

---

## 중요 규칙

파일명을 기준으로 커밋 메시지를 만들지 않는다.

무엇을 수정했는지가 아니라

왜 수정했는지를 기준으로 작성한다.

---

## SafeCheck 규칙

기술 선택이나 설계 결정은 커밋 메시지에 작성하지 않는다.

아래 내용은 Work Log 또는 ADR에 기록한다.

- 기술 선택 이유
- 후보 비교
- 트레이드오프
- 상세 설계 내용

커밋 메시지는 한 줄로 변경 목적만 설명한다.
